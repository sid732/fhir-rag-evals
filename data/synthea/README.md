# Synthea cohort

Everything in `data/cohort/` is synthetic. It is generated by [Synthea](https://github.com/synthetichealth/synthea) (Apache-2.0) and contains no real patient data.

## Regenerate

```bash
make data
```

`generate.sh` downloads the pinned jar to `~/.cache/fhir-rag-evals/`, checks its SHA-256, runs Synthea in a temp directory, and writes gzipped bundles plus `MANIFEST.sha256` to `data/cohort/`. Running it again should leave `git status` clean. If it doesn't, the cohort isn't reproducible on that machine, and the gold labels (which point at resource IDs) need checking before anything else.

## Pinned inputs

| Input | Value | Why it's pinned |
|---|---|---|
| Synthea | v4.0.0, jar SHA-256 `ed43c20a…e6ecc1` | Output depends on the version |
| Seed (`-s`) | 20261020 | Defaults to the current time |
| Clinician seed (`-cs`) | 20261020 | Defaults to the current time |
| Reference date (`-r`) | 2026-10-01 | Defaults to today; ages (`-a`) are measured at this date |
| End date (`-e`) | 2026-10-01 | Defaults to the moment Synthea starts, so without it every rerun adds new history |
| Population (`-p`) | 15 living patients | Small enough to commit and to review by hand |
| `generate.only_alive_patients` | true | When a simulated person dies early, Synthea retries with a new one and by default exports the dead attempt too; those records end decades ago |
| Ages (`-a`) | 35 to 85 | Adult records have chronic conditions, labs and medications to ask about |
| State | Massachusetts | |
| `exporter.years_of_history` | 10 | Keeps bundles small; active conditions and medications are exported regardless |
| `exporter.fhir.use_us_core_ig` | true (US Core 6.1.0) | US Core profiles; also turns on the per-encounter clinical notes |
| `exporter.fhir.transaction_bundle` | true | One transaction Bundle per patient, loadable into a FHIR server |

## Dates after the end date

A few fields are later than 2026-10-01. They come from the simulation, not the clock, and are identical across runs:

- `ExplanationOfBenefit.billablePeriod.end`: one year after the billing period starts.
- `Device.expirationDate`: expiry dates of devices the patient has.
- `Provenance.recorded`: when each patient's simulation stopped. Synthea moves in 7-day steps, so this can land up to a week after `-e`.

## Files

- `<patient-uuid>.json.gz`: one FHIR R4 transaction Bundle per patient.
- `hospitalInformation.json.gz`, `practitionerInformation.json.gz`: the organizations and practitioners that patient bundles reference.
- `MANIFEST.sha256`: SHA-256 of the JSON inside each file. Eval reports record this file's hash as the cohort version.
